# 本地化与三语支持

UrbanPlanToolbox 当前正式支持三种界面语言：

| 语言 | BCP-47 |
| --- | --- |
| 简体中文 | `zh-CN` |
| 日本語 | `ja-JP` |
| English | `en-US` |

默认与最终回退语言为 `zh-CN`。

## 用户如何切换语言

设置页提供：

- 跟随系统 `system`
- 简体中文 `zh-CN`
- 日本語 `ja-JP`
- English `en-US`

当前运行时切换机制会保存语言偏好、刷新本地化资源并重建现有 Shell 视觉树，因此不应再要求用户为了正常切换语言而重启应用。

## 哪些内容会跟着语言变化

界面资源包括：

- 导航与页面标题
- 工具名称和说明
- 分类名称
- 搜索关键词
- 操作按钮和状态文本
- 专业资料库中已经提供三语元数据的字段

工具搜索会基于当前界面语言解析名称、说明和关键词。

## 哪些内容不会被自动翻译

语言切换不会改写用户数据。

以下内容保持原样：

- 用户输入
- 项目正文
- 灵感文本
- 收藏所保存的稳定工具 ID
- 项目 / 工具 / 路由等内部稳定 ID
- 文件名
- URL
- 版本号
- 单位符号
- 程序代码

这可以避免切换界面语言时意外修改项目资料。

## 资源结构

界面文案使用 MRT Core 资源目录：

```text
Strings/
  zh-CN/Resources.resw
  ja-JP/Resources.resw
  en-US/Resources.resw
```

三套 `Resources.resw` 必须拥有完全相同的键集合。

静态 XAML 文本优先使用 `x:Uid`；动态文本统一通过 `ILocalizationService` 获取。页面不应自行创建另一套 `ResourceLoader` 或引入第三方在线翻译框架。

## 新增或修改文案

贡献者修改界面文字时，应：

1. 同时维护三套 RESW 中的相同资源键；
2. 使用稳定英文语义名，不把中文 / 日文显示文字作为 ID；
3. 保持格式字符串 `{0}`、`{1}` 等占位符数量和编号一致；
4. 不把颜色、尺寸或业务常量塞进字符串资源；
5. 运行本地化测试，确认键集合一致且无空值。

## 专业术语与普通 UI 文案

规划术语、法规元数据与设计理念属于专业数据，不应简单混入 UI 字符串资源。

从 v1.9.2 起，这些专业资料由 Data Pack 管理。v1.9.3 又补齐了设计理念分类、项目类型、标签、案例说明和来源说明的三语元数据。

因此：

- UI 文案 → `Strings/*/Resources.resw`
- 专业知识内容 → Data Pack
- 用户数据 → 保持用户原始内容

三者应保持边界清晰。

## 新增语言时

工程规范要求至少完成：

1. 新建 `Strings/<BCP-47>/Resources.resw`；
2. 复制并翻译完整资源键集合；
3. 在 `Package.appxmanifest` 中声明语言；
4. 更新 `LanguagePreference.SupportedBcp47Languages`；
5. 在设置页增加显示选项；
6. 补充解析、搜索和运行时切换测试；
7. 验证最终 MSIX 中真实存在对应语言候选资源。

仅仅“源码里有 RESW”不能视为发布包已经正确包含该语言。

## 翻译审校原则

现有三语资源是开发基线。专业规划术语、日语自然度、英语母语表达、文字长度和视觉层级仍应通过人工审校维护。

如发现翻译问题，优先做局部、可追踪修正，而不是在没有上下文的情况下批量替换全部术语。
