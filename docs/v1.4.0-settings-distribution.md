# v1.4.0 Foundation — Settings & Distribution

## Settings audit

| Setting | Storage | Type/default | Reader/writer |
|---|---|---|---|
| Theme | `settings.json` / `Theme` | `AppTheme`, System | `SettingsService`, SettingsPage, theme application |
| Language | `settings.json` / `Language` | supported BCP-47 or system | `SettingsService`, LocalizationService, SettingsPage |
| Decimal places | `settings.json` / `DecimalPlaces` | integer, 2 | `SettingsService`, calculator/converter pages |
| Auto calculate | `settings.json` / `AutoCalculate` | bool, false | `SettingsService`, existing model compatibility |
| Milestone notifications | `settings.json` / `ProjectMilestoneNotificationsEnabled` | nullable legacy, safe false | `SettingsService`, MilestoneReminderService |
| Reminder repeat interval | `settings.json` / `ProjectMilestoneReminderRepeatInterval` | enum, None | `SettingsService`, MilestoneReminderService |
| Favorite tool IDs | `settings.json` / `FavoriteToolIds` | stable ID list, empty | `SettingsService`, FavoriteToolsService |
| First-run state | separate `first-run-guide.json` | schema 1 state | FirstRunExperienceService only |

There are no direct UI callers of `ApplicationData.Current.LocalSettings`.
First-run state is intentionally separate from user preferences and backup
data. `SettingsKeys` is the canonical key list. Reads are case-insensitive for
legacy JSON, values are normalized, and a malformed individual property falls
back to its field default without discarding valid sibling fields.

## Distribution call chain

```text
Package.Current.Id (exact Name/Publisher/PublisherId)
  -> AppDistributionChannelService
      -> DistributionChannelContext
          -> AppUpdateServiceFactory
              -> GitHubAppUpdateService
              -> StoreAppUpdateService
              -> DevelopmentAppUpdateService
```

GitHub sideload, Microsoft Store, and unpackaged development now have explicit
capabilities. About consumes the context for channel display and button
capabilities; it does not re-detect the channel. Development builds do not
pretend to be GitHub installations and do not invoke either release updater.
